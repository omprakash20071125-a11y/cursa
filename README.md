# 🎓 cursa

An AI-powered personalised learning app that takes any topic, breaks it into 5 structured subtopics, fetches curated resources for each, and tests your understanding with a quiz before letting you advance.

---

## What It Does

1. **You enter a topic** — e.g. "Transformers in NLP", "Docker Networking", "Calculus Derivatives"
2. **AI generates 5 subtopics** — ordered from foundational to advanced using Groq (Llama 3.3 70B)
3. **Resources are fetched** — 3 curated links (videos, articles, hands-on) via Tavily search for each subtopic
4. **You take a quiz** — 5 MCQ questions generated by AI on that subtopic
5. **Score ≥ 75% to advance** — fail and you get a fresh quiz on the same subtopic
6. **Final report** — overall score breakdown across all subtopics at the end

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Streamlit |
| Agentic Backend | LangGraph (StateGraph with interrupt/resume) |
| LLM | Groq API — Llama 3.3 70B Versatile |
| Resource Search | Tavily Search API |
| State Persistence | LangGraph MemorySaver (in-memory) |
| Data Validation | Pydantic |

## Getting Started

### 1. Clone the repo

```bash
git clone https://github.com/yourusername/ai-tutor.git
cd ai-tutor
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Set up environment variables

Create a `.env` file in the root:

```env
GROQ_API_KEY=your_groq_api_key_here
TAVILY_API_KEY=your_tavily_api_key_here
GROQ_MODEL_NAME=llama-3.3-70b-versatile
```

Get your keys here:
- Groq: https://console.groq.com
- Tavily: https://app.tavily.com

Both have free tiers.

### 4. Run the app

```bash
streamlit run app.py
```

Open `http://localhost:8501` in your browser.

## How the Backend Works

The backend is a **LangGraph StateGraph** — an agentic workflow where each node does one job:

```
START
  └─► generate_subtopics        # LLM generates 5 ordered subtopics
        └─► fetching_resource   # Tavily fetches 3 resources for current subtopic
              └─► generate_quiz # LLM generates 5 MCQ questions
                    └─► answer_collector   # ← INTERRUPT: waits for user answers
                          └─► score_calculator
                                └─► [conditional routing]
                                      ├─ passed + more subtopics → increment_counter → fetching_resource
                                      ├─ passed + all done       → END
                                      └─ failed                  → generate_quiz (retry)
```

The **interrupt/resume pattern** is what makes this work as a proper human-in-the-loop system — the graph pauses at `answer_collector`, the Streamlit frontend collects answers, then resumes the graph with `Command(resume=answers)`.

## Known Limitations

- **In-memory state only** — if the server restarts, session progress is lost. A production version would swap `MemorySaver` for a persistent checkpointer (Redis, PostgreSQL).
- **No user accounts** — each browser session is independent, progress is not saved across sessions.
- **Tavily free tier** — limited to 1000 searches/month. Resources may occasionally fall back to a Google search link.
- **Groq rate limits** — on the free tier, rapid back-to-back quiz retries may occasionally hit rate limits.
